# Start here: ARK research method and AI onboarding

**Current methodology edition: 1.1 - 3 October 2026.**

Before deciding what ARK establishes, understand how its claims are constructed and tested. This folder is the repository's starting point for human and AI collaborators. The task is to learn a research discipline, not adopt a prescribed physical conclusion.

> Independently measured inputs can produce genuine predictions through fixed balance relationships. Reciprocal equations and coupled closure are not automatically circular. Identify actual target leakage or answer-forcing choices; also recognize legitimate calibrated and cross-domain prediction.

## Reading order

1. [AI onboarding brief](AI_Onboarding_Brief.md): the working contract and metrological stance.
2. [Prediction, closure, and mechanism](Prediction_Closure_and_Mechanism.md): paired examples of legitimate inference and misleading agreement.
3. [Full epistemic charter](ARK_Epistemic_Charter.md): approximately 15,000 words, 18 main sections, 14 historical cases, seven research-record templates, and 18 assessment scenarios.
4. The actual technical specification, data definitions, claim status, and negative-result records for the task you are about to perform. This charter is not a replacement for those artifacts.

For a first methodological review, prioritize charter Sections 1.4, 6, 7, 12, and 14.7. Before coding or empirical evaluation, also read Sections 4-11 and 15-18. Use the Word edition for human reading; Markdown is the canonical repository text.

## Practice and reusable records

[Research-record templates](Research_Record_Templates.md) contain the claim record, pre-run specification, negative-result record, drift entry, session handoff, measured-input / cross-domain record, and ASRP intervention record.

Attempt the [assessment questions](Onboarding_Assessment.md) before consulting the [rubric](Onboarding_Rubric.md). This public question bank is practice, not a sealed evaluation. A formal capability assessment needs new cases and a record of what the collaborator has already seen. Correctly accepting a legitimate prediction matters as much as detecting a contaminated one.

The [synthetic executable examples](examples/test_epistemic_examples.py) check elementary teaching calculations. Passing them does not validate ARK, its physical mechanism, or an AI's independent research capability.

[CHANGELOG.md](CHANGELOG.md) records the correction from v1.0 and the source-file provenance. Historical physical results were not re-executed for this documentation release.

## Source-access limits

The full charter retains the source register and historical examples from the original v1.0 review. Source C1, Paper XXV, and source C6, Paper XVIII v3, have corresponding PDF files in this repository's root. Their presence was checked; their contents were not re-audited for this release.

Sources C2-C5 refer to consolidation, session, and negative-result records reviewed for v1.0. Those source files were not present on the inspected default branch and are not bundled here. Retrieve the exact source from the project owner or an identified research branch before relying on its underlying calculation. A quotation in this charter is not independent source access. Do not search or publish unrelated personal session content.

The original v1.0 documents are preserved in the project owner's downloadable handoff bundle; they are not included as duplicate public files in this folder. The changelog records their hashes. References to the accompanying release archive in the charter refer to that handoff bundle, not a GitHub Release asset.

## Version and authority

This folder states the current collaboration method. It does not silently resolve evolving scalar definitions or promote historical claims. When prose, code, or papers conflict, identify the actual model version and the unresolved bridge rather than choosing whichever wording favors a result.

The physics repository holds the canonical full charter. The AI-and-Cognition repository provides a local entry guide and a version-pinned route to this edition. Read the recorded version before assuming a later edit has the same content.

Root README and AGENTS.md point here to make the method discoverable. Repository files cannot guarantee that every AI client will read or obey them; report which documents were actually read.
